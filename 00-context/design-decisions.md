# 设计决策记录 (Design Decisions)

## 1. 核心布局演进 (Layout Evolution)

### 初始设计
- **结构**：单一大列表，目录与内容混排。
- **问题**：层级不清晰，难以快速跳转章节；目录占用过多垂直空间。

### 迭代 v1 (侧边栏布局)
- **结构**：左侧固定侧边栏（目录树），右侧资源列表。
- **改进**：实现了章节导航与内容浏览的分离。
- **问题**：移动端适配性差，侧边栏挤占内容区。

### 最终方案 (响应式双栏 + 抽屉)
- **桌面端**：保持左侧目录树 + 右侧资源流的双栏布局，利用宽屏优势。
- **移动端**：侧边栏改为浮动抽屉（Drawer），通过左侧边缘的"拉手"按钮或点击章节标题唤起。
- **双向联动**：实现目录点击 -> 内容滚动，以及内容滚动 -> 目录高亮的双向同步，提升沉浸式阅读体验。

## 2. 导航与功能区 (Navigation & Function Bar)

### 决策：层级重组
为了理清"全局筛选"与"当前视图操作"的关系，我们重新划分了顶部区域的职责：

- **GlobalHeader (L1)**：承载全局上下文选择。
  - **内容**：[返回] + [学段/学科/教材选择器] + [升级入口]。
  - **理由**：学段学科是最高层级的过滤器，决定了整个页面的内容范围。

- **FunctionBar (L2)**：承载当前视图的过滤与工具。
  - **内容**：[场景 Tab (全部/预习/复习/加餐)] + [快捷工具 (思维导图/错题本/设置)]。
  - **理由**：场景 Tab 是对当前学科内容的二次筛选；快捷工具辅助当前学习过程。

## 3. 场景 Tab 与"全部"视图 (Scene Tabs)

### 决策：Unified Scene Tabs
- **问题**：早期方案中"全部资源"作为一个独立按钮存在，与场景 Tab 割裂，导致用户困惑。
- **方案**："全部"作为 Scene Tabs 的第一个固定选项，与预习/复习/加餐并列。
- **交互**：切换到"全部"时，展示该章节所有资源，并显示通用的课程特点介绍；切换到特定场景时，仅展示对应资源和场景建议。

## 4. 复习模式学习顺序 (Review Mode Learning Order)

### 决策：教学法的系统化支持
针对复习场景，教学法上存在"先测后学"与"先学后测"两种路径。为了尊重用户习惯同时引导科学学习，我们设计了：

- **选择机制**：在复习场景下点击知识点卡片，弹出模态框询问学习顺序。
  - 选项 A：先做题后看视频（推荐，高亮显示）
  - 选项 B：先看视频后做题
- **偏好记忆**：用户可选择"记住我的选择"，后续自动应用。
- **可配置性**：在设置页面可随时修改此偏好，或重置为"每次询问"。

## 5. 设置系统 (Settings System)

### 决策：引入独立设置页
随着个性化需求的增加（如复习顺序、默认首页、难度偏好），FunctionBar 已无法承载。因此引入独立的设置页面：

- **入口**：位于 FunctionBar 右侧（移动端折叠在"≡"汉堡菜单中）。
- **页面模式**：覆盖主内容区的独立视图，保持轻量级，不跳转路由。
- **管理范围**：
  - 复习学习顺序
  - 默认进入的场景 Tab (全部 vs 上次选择)
  - 同步刷题的默认难度筛选

## 6. 技术架构 (Technical Architecture)

- **状态管理**：使用 Pinia (`chapter.ts`) 集中管理章节数据、用户偏好 (`AppSettings`)、VIP 状态和 UI 状态（如侧边栏开关）。
- **持久化**：`AppSettings` 自动同步至 `localStorage`，确保用户偏好跨会话保持。
- **组件化**：采用原子化组件设计（`KnowledgeCard`, `LearningModeModal`），提升复用性与维护性。
